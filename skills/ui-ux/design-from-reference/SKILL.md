# Design From Reference

## Core principle

A reference is a source of structural and stylistic information, not something to be
cloned wholesale. Extract the reasoning (why it is laid out this way, how it builds
hierarchy) and apply it to the current product. Respect the rights of the original.

## Operating procedure

1. **Confirm the goal and permissions.** Is this the user's own design, a third-party
   site for inspiration, or something they have the right to reproduce? Do not reproduce
   copyrighted assets (logos, illustrations, proprietary icons, photography) without a
   clear right to do so. When in doubt, reproduce *structure and principles*, not the
   exact protected assets.

2. **Analyze systematically.** Break the reference down:
   - **Layout** - grid, columns, alignment, container widths, region proportions.
   - **Hierarchy** - which elements dominate, how the eye travels, what is de-emphasized.
   - **Typography** - scale relationships, weights, line lengths, rhythm.
   - **Color and contrast** - palette roles, background treatment, accent usage.
   - **Spacing** - density; consistent rhythm; where breathing room is used.
   - **Component patterns** - how recurring elements (cards, nav, buttons) are built.
   - **Interaction cues** - affordances, hover/focus treatment, feedback.

3. **Decide what to carry over and what to change.** The current product has its own
   identity, content, and constraints. Carry over the *principles* and adapt specifics.
   Changing the content and then applying the reference layout verbatim often produces
   something that looks transplanted rather than designed.

4. **Reproduce only what you can measure.** If you can inspect the reference (colors
   sampled, spacing measured), you can reproduce those values. If you are estimating by
   eye from an image, say so. Do not claim pixel-perfect fidelity from an eyeballed
   approximation.

5. **Reuse real assets only with rights.** Use the product's own icons, fonts, and images.
   If the reference uses a font or icon set you do not have licensing for, substitute an
   equivalent - do not embed the protected asset.

6. **Verify against the reference.** Compare the result structurally: same regions, same
   hierarchy, similar density. Note intentional differences.

## Quality criteria

- The reference was analyzed along the dimensions above, not copied blindly.
- The result adapts the reference's principles to the current product's content.
- No protected assets were reproduced without a clear right to.
- Fidelity claims match how the reference was obtained (measured vs. estimated).

## Anti-patterns to avoid

- Embedding the reference's logo, illustrations, or proprietary icons.
- Claiming "pixel-perfect" from visual estimation.
- Cloning layout verbatim when the content and product identity are entirely different.
- Copying a distinctive, recognizable visual identity as if it were the product's own.
- Ignoring the difference between "inspired by" and "copied from".

## Validation strategy

- Confirm every reused asset is either licensed for reuse or substituted.
- State the fidelity basis: measured (tools used) or estimated (visual comparison).
- Compare the output to the reference on layout, hierarchy, and density; list deliberate
  differences.

## Ethics and legal note

This skill does not provide legal advice and cannot determine whether a given use
infringes. When a reference is another party's design, the safe path is to adopt
structural principles and use the user's own brand assets. Flag any uncertainty to the
user rather than proceeding on an assumption.
